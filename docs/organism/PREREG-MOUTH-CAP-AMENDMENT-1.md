# PREREG-MOUTH-CAP — AMENDMENT 1 (before any code of this law is committed): the budget counts READ-BACKS; n_unique exact except on the budget path

*Author and seat: Kimi K3 (kimi-code, alone — Ahmad's 2026-10-05 word). Caught in the build walk, before any code commit, by running the existing mouth tests against the considered-form draft: two failures that were the law's own drafting defect, not the tests'.*

1. **The drafting defect.** The signed §2 declared the budget to count candidates CONSIDERED («each uniqueness evaluation = 1; the read-backs are a subset»). Walked against the say sizes it must govern, that form is a bar that bites below its intent (#228 (b)'s class): a say of 12 spends 4,095 of the 4,096 on uniqueness evaluations alone and leaves ONE read-back — the budget would fire the overflow form on canvases whose mouth is perfectly cheap, and a say ≤ 11 spends so much of the budget on uniqueness that the read-back room varies with the class structure instead of the cost. The expensive unit is the READ-BACK (the pilot's measured 4.7 ms; a uniqueness evaluation is ~µs, and the OLD code already paid the full 2^N uniqueness pass on every canvas — it materialized and filtered the whole list).
2. **The amended form.** `MOUTH_BUDGET = 4096` counts **read-backs** (`answer_point` calls), the unit the law's price arithmetic already uses (4,096 × 4.7 ms ≈ 19.3 s, unchanged). Uniqueness is streamed per length class (never a materialized list — the memory point of §2.1 stands) and is evaluated for EVERY candidate on every path except the budget path, so **`n_unique` is exact whenever the budget does not bind** — a TIGHTENING of the signed text's prefix form, never a loosening: on the closed record (say ≤ 3 → 7 candidates) every counter is now bit-identical to the old code's, which the existing tests pin (`tests/brain/scene/test_learners_s1b1r.py:237,248` — the two assertions the considered-form draft failed). `n_accepted` on the early-stopped path stays the declared prefix (the read-backs are the enumeration being bounded), under `"exhaustive": false`; it is not journaled and no test or grader reads its value (verified by grep 2026-10-05: one presence-only assertion in `tests/genome/test_brain_organ.py:313`).
3. **Consequences for the signed text.** §2.2's «candidates CONSIDERED (each uniqueness evaluation = 1)» reads «read-backs»; §2.3's «`n_unique` / `n_accepted` … report the CONSIDERED prefix» reads «`n_unique` exact except on the budget path; `n_accepted` the considered prefix»; M-BUDGET's «`n_considered` == the budget» reads «`n_readbacks` == the budget». No bar, no gate form, no verdict row moves; M-TIME's bound (≤ 60 s) and its arithmetic stand (the uniqueness floor is strictly ≤ the old code's own per-canvas uniqueness cost — the old code paid the same 2^N pass with list-building on top).
4. **The walk that owes nothing more:** the budget path's `n_unique` is a prefix (the break lands mid-class) — declared, under `"exhaustive": false`, never on the closed record (the record's say ≤ 3 needs ≤ 7 read-backs of 4,096).
