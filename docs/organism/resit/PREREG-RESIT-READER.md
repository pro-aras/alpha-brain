## 0 · The question, and what is built

The architect's forgetting prediction (HEARS-2 AMENDMENT 2 A2.1): once `brain-long-3` hears the maker's world for days, the scene words decay, colour and size first. **The reader answers one thing and no more: what does the brain, as saved, answer on the SAME 3,011 sitting asks over the SAME canvases?** Items, canvases, grader and the reader's code are fixed; only the brain's state moves, so a difference between two states is exact for these items. **What it is read AGAINST is the brain at the sittings, rebuilt (§5) — never a daily copy.**

Built, in this order (the seat's): (1) `tools/brain/resit.py` + `tests/tools/test_resit.py` + `deploy/creature-brain-resit@.service`/`.timer` (written, **not enabled** — the seat enables it for `brain-long-3` after launch): R1 on the closed `brain-long-2` first, then R2–R9, R11–R14; (2) **after R1 passes**, `tools/brain/rebuild_origin.py` + its tests (§5, R10); (3) then EVOLVE-CAL's build, unless the seat reorders. **Builder: CLAIMS (Claude Sonnet 5.5, swarm claims) for all three.** The reader never writes under a life's root, never calls `Brain.learn`, never calls `Brain.turn` outside R14's test on a copy, never touches a life's unit, and never imports `creature.mind`; the rebuild imports it (it replays the mind) and writes only under its own `--out`.

## 1 · One run

### 1.0 Which code is whose (A3 i–iii) — fixed before any code

- **Run BY PATH, never `-m`:** `python3 -B -I tools/brain/resit.py …`. The orchestrator process imports the standard library only, and refuses to run unless `sys.flags.dont_write_bytecode` is set (a cold import of `tools/brain/grade_life.py` — which the mind never imports — would otherwise write `<root>/code/tools/brain/__pycache__/*.pyc` INTO the live root) and unless `OPENBLAS_NUM_THREADS` and `OMP_NUM_THREADS` are `1` in its environment, as the life's own unit sets them (a brain state's float bits depend on the BLAS thread count, #246 (8)); both are recorded in the row. `-I` ignores `PYTHON*` variables, so hash randomisation is ON with a fresh seed per process (R2 reads that as a feature).
- **Two child processes, each run BY PATH with the same flags; no module of the life and of the grader ever meet:**
  - the **ANSWER child (the SUBJECT)** puts `<code>` first on `sys.path` BEFORE importing anything of `genome`, `brain`, `creature`, `tools`, then imports the life's own `genome.brain`, `genome.gaze`, `genome.machinery`, `creature.tape`, `creature.organs_road`, `brain.scene.*`. **After the imports it ASSERTS that every loaded module of those four packages has its realpath under `realpath(<code>)`** (a package imported earlier from elsewhere keeps master's `__path__` and silently serves master's submodules; `-m tools.brain.resit` does exactly this) and writes each file's sha256 into the row. `<code>` defaults to `<root>/code`, the checkout the life runs.
  - the **GRADE child (the GRADER)** is **the instrument's file, loaded by path from a PINNED commit that carries HEARS-2 AMENDMENT 4's grader** (`--grader-code <dir>`: a checkout of that commit; brain-long-3's learned types will hold maker words, and a grader without A4 crashes on exactly that, WorldError «arrow»). This is the second of the architect's two holds; the SUBJECT (brain, gaze, organs_road, tape) stays the life's. The pin (commit sha, the sha256 of `tools/brain/grade_life.py` and of every module the child loaded) is written once into `OUT/GRADER.json` at the first run; a later run under another pin is REFUSED. The answers cross from one child to the other as plain JSON.
- **The unit** (`deploy/creature-brain-resit@.service`) is its own cgroup with `CPUWeight=10` and `Nice=15` (`nice` divides a cgroup, never the box, #247 (4)), `-B -I` in its `ExecStart`, the two BLAS pins in its `Environment`. R12 reads the live life's load before and during the run.

### 1.1 The state — three sources, one mode each

- **S1 `--mode daily`:** `<root>/state/prev/` (the last COMPLETE snapshot generation, hard links). Read `prev/SNAPSHOT.json` `{files, last_seq, prints, t}`; `shutil.copy2` `brain.json` and `brain.npz` into `OUT/days/<stamp>/copy/`; each copy's `(size, mtime_ns)` must equal `prints`; a mismatch is retried 3 times, 20 s apart (a generation is being replaced), then the day is REFUSED by name. `Brain.load(copy/"brain", cfg)` adds its own check (the files must hash to the hash they carry).
- **S2 `--mode origin`, rebuilt (seat (i)):** `--state [SET=]DIR`, repeatable; DIR holds a `brain.json` + `brain.npz` pair **outside `state/prev`**, still hash-checked by `Brain.load`. `--state fresh=DIR1 --state s1b1=DIR2` answers the fresh items against the fresh-begin state and **the s1b1 items against the s1b1-begin state** (the brain learns maker canvases INSIDE a sitting: 126 in fresh and 114 in s1b1 on the bench); a bare `--state DIR` serves every set. A rebuilt DIR must also hold the rebuild's `ORIGIN.json` and `GENOME.in-force.genome` (§5): a bare pair of unknown provenance is REFUSED by name, its `state_hash` must equal the loaded copy's, the genome file's sha256 must equal the sidecar's. The copy is verified by sha256 against the source (no manifest of mtimes exists for an out-of-tree state).
- **S3 `--mode origin --origin-kind fallback_copy` (HEARS-2 A2.3 (6)(c)):** DIR is the seat's read-only copy of `state/prev` taken when `STATUS.json` showed the scene world ended (it carries its own `SNAPSHOT.json`, checked as S1). **Refused without `--reason "<the seat's words>"`**, which is recorded verbatim; every row paired against it prints `FALLBACK ORIGIN — late by at most one snapshot`. The reader cannot know whether (a)'s pilot failed: it records the seat's say.

### 1.2 The genome in force (A2, AM2, AM3) — the rule, not «the highest `GENOME.v<n>`» (v1's rule, withdrawn)

The eye (RETINA, GAZE, SENSE colour) and the BRAIN config are those of **the genome in force when the compared state or answers were made**. The journal records an adoption as a row with an **`epoch` KEY** (not an `event` value): `{"seq": 211015, "epoch": {"epoch": 1, "genome_sha": "fd15f9e3…", "moment": 400200, "gene": "KWTA.k", "value": 4, "proposal_no": 5}}` — brain-long-2's journal holds exactly ONE (1 matching line over its five day files, in 2026-09-30.jsonl; 0 rows with `event: "epoch"`), and its `genome_sha` equals `sha256(GENOME.v1.genome)` (checked 12:37). The in-force epoch k is the highest whose row seq is: **(AM3) in gate mode (R1, R1′, R9, R10d/e) and for the rebuilt origin (S2) < the sitting set's `begin` ask seq** — the genome under which the life's own answers to that set were made, and the one the rebuild saves beside each state (v2 applied the daily rule to R1, which picked epoch 1 for brain-long-2 and passed only because epochs 0 and 1 have equal eye lines: the luck this section says it avoids); **in daily mode (S1) and for a fallback copy (S3) ≤ the state's `last_seq`**. The file is `GENOME.v<k>.genome` (k ≥ 1) or `GENOME.genome` (k = 0), and for k ≥ 1 its sha256 **must equal the epoch row's `genome_sha`**, else REFUSED. A root with `GENOME.v<n>` files and no readable epoch row is REFUSED (undetermined), never defaulted.
Every row carries the sha256 of the **RETINA, GAZE, SENSE colour and BRAIN lines** (canonical JSON of the parsed objects) and of the whole genome. **EVOLVE cannot move any of those four lines (AM2; v2's sentence saying `BOUNDS` «holds six keys that move the eye» is withdrawn as wrong):** `creature/genes.py` holds the seven eye/sense keys (GAZE.fixations, .grid, .canvas, .glance, RETINA, SENSE.colour, SENSE.ear_letters) as `excluded: True` entries, `MUTABLE_KEYS` (15 keys of 32) filters them out, `apply_mutation` raises on them, and BOUNDS holds no BRAIN key at all. **So a row whose four line-hashes differ from the origin's is marked EYE-CHANGED and is an ANOMALY:** the genome changed by a road EVOLVE does not have (a hand edit, or a code change). The row is written; its pairing is printed only as a labelled reading; no verdict copy is ever read from it (if the verdict-copy flag of §4.6 lands on such a row, the row says so). R13 pins the premise structurally. **R1 on brain-long-2 runs under epoch 0** (gate mode, AM3): its one adoption (seq 211,015, KWTA 5 → 4: the files differ in that ONE line, which neither the gaze nor the brain's ask road reads) lies after both begin asks; the four line-hashes of epochs 0 and 1 are printed as a READING (equal, as the bounds predict), not as a premise the gate stands on. **(v4) Gate mode refuses an eye change between the sets:** in gate mode (R1, R1′) the in-force genomes of the two sets must carry equal RETINA, GAZE, SENSE colour and BRAIN lines, else the gate is REFUSED by name (EYE-CHANGED between the sets: one brain copy cannot be read under two eyes); daily and origin rows keep AM2's rule (written and labelled, never refused). **(v4) The GRADER's genome — one configuration for the origin and the daily rows:** `grade()` reads from its genome argument exactly these lines and no other: the `WORLD scene` line (`seed`, `train`, `sitting`), the `TAPE` path, and `RETINA`, `GAZE`, `SENSE colour` (for `meeting_seen`'s own look; checked by grep over every `genome`, `declared` and `cfg` use in `tools/brain/grade_life.py`, 2026-10-03). The genome argument of the GRADE child is the pinned one — `<items root of ITEMS.json>/GENOME.genome`, brain-long-2's — for every daily row AND the origin, with the same `--scored`; only the tape root of the origin's grade changes (the source copy, §1.6). Every daily and origin row prints the grader genome's file sha256 and the hashes of the lines it reads (WORLD scene, TAPE, RETINA, GAZE, SENSE colour) and of its BRAIN line, the same hashes for the life's in-force genome, and **EYE-CHANGED has two forms:** (i) within the life (AM2, unchanged): any of RETINA, GAZE, SENSE colour, BRAIN of this row's in-force genome differs from the origin's; (ii) against the grader: any of RETINA, GAZE, SENSE colour, WORLD scene, TAPE of the life's in-force genome differs from the grader genome's. Either form is an anomaly, labelled, and no verdict copy is read through it. **The BRAIN line is not compared across lives:** brain-long-2 and brain-long-3 differ in it by the ladder's own design (measured: the two launch genomes differ in that one line, the calibration schedule and `hears scene maker`), `Brain.load` demands the saved cfg equal the life's own BRAIN line, and the grader never reads it; both BRAIN hashes are printed as a reading. (The architect's condition (2) reads «any of the four»; the form above is the author's reading of it, flagged in §8 for the co-signature.)

### 1.3 The items (A4)

`--items-root` is explicit and **pinned** in `OUT/ITEMS.json` at the first run: `{root, n_asks, ask_digest (sha256 over the sitting asks' payload bytes in seq order), canvas_digest (sha256 over the sitting eye rows' `sha` in seq order), world_scene_line_sha, scored (path + sha256 of `scored/<ws>/fresh/marks.json`)}`; every later run re-checks it, and the SAME `--scored` reference is used every day. **For `brain-long-3` the items root is `brain-long-2`'s root** (the same seed's fixed sittings; brain-long-3 has no daily sitting — its own sittings happen once, at its scene stream's end, and are the origin's). **(v4)** In the origin run (only) the answers are taken over the LIFE's OWN sittings, so that every answer row carries the life's own `seq`, `eye_seq` and `at` and R9 can compare rows exactly: the items root of the origin's ANSWER and GRADE children is the SOURCE COPY of §1.6 (never the live root), after **ITEMS-MATCH** (R15) has proved on that copy — FIRST, and before either child is started — that its sittings are the pinned items: `ask_digest`, `canvas_digest` and `world_scene_line_sha` equal ITEMS.json's, and every sitting canvas's payload bytes hash to the tape row's `sha`; a difference REFUSES the origin by name (the series would not be about the life's sittings). The origin row's vectors are keyed by item NAME, so the pairing against daily rows (taken over brain-long-2's tape) is untouched. The items root of a daily or gate run is a CLOSED life's root, read only.

### 1.4 The answers (the mind's own order, nothing learned)

Rows of the items root in tape order (`creature.tape.read_tape`): a canvas-less form (`begin`, `end`, `why`) is answered AT its ask row; every other form is held for its moment's eye row and answered there (`creature/mind.py`: `_consume_ask`, `_brain_canvas`); no other row is touched. At a held ask's eye row: `gaze.glances(rgb, retina, gaze, "surprise", row["sha"], colour=genome.colour, predicted=None)` — the call `_consume_eye` makes (a sitting canvas carries no ear word) — cached in `OUT/glances.pkl` under a content key (`sha` + the in-force RETINA/GAZE/colour line-hashes, #245). `brain.ask(payload, g)`; a `BrainError` is ANSWERED `refused`, as the mind does. The row is the mind's own `{"kind":"answer","by":"brain","item","mark","form","answer","moment","seq","eye_seq","at","fix","hyps","detail"}`, `fix`/`hyps` from `creature.organs_road.eye_view(g)`, `answer` through a ten-line copy of `_jsonable` pinned by a parity test. `begin` may calibrate the COPY (`Brain.ask` does so when `n_learned > 0 and calibrated_at != n_learned`) — the life's own sitting protocol; every row records `calibrated` and `calibrated_at` before and after. S2 switches to the set's own state at that set's `begin` row.

### 1.6 The origin's SOURCE COPY (v4; the seat's binding point (1), RULES 7)

## 7 · Adversarial walk

1. **Can R1 pass without the reader being right?** Only if the reader copied the life's rows: it recomputes the glance from the TAPE's PNG and the journal row is what it is compared WITH; R3 nudges a COPY and must change answers computed from the tape.
2. **Can R1 fail for a reason that is not the reader?** Four: the brain moved after the sittings (P0 over the fail-closed act set, measured: it did not — R1 would read NOT GRADABLE, not a defect); a different code (hence `<code>`, asserted by realpath, R11); a different genome (the rule of §1.2 — in gate mode the genome in force at each begin ask, epoch 0 — hash-checked); a restart inside a sitting that left two unequal rows for one ask (RESTART-DIVERGENT, R4 k, 0 expected).
