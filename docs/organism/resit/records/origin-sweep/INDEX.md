*(edit: Claude (Sonnet 5.5, swarm claims), 2026-10-03 22:02 +0400 (from `date`). Everything in the tables below is computed from the sweeps' own logs in `logs/` by `make_sweep_index.py`; no verdict is typed by hand. The method, the sweeps' shas and the honesty notes are the only prose.)*

## What a sweep is here

`mutate_origin.py` holds a list of MUTANTS: each replaces ONE string (an anchor that must occur exactly once) of `tools/brain/resit.py` by a broken version of ONE thing the law (PREREG-RESIT-READER v4 + erratum E1) relies on, runs the origin tests (`tests.tools.test_resit_origin`, `tests.tools.test_resit_origin_copy`) and the early/late class tests (`tests.tools.test_resit.TestEarlyLate`), then restores the file and checks its sha256. A mutant is **CAUGHT** when a failing test's name contains one of the substrings the mutant NAMES in advance (the test written to catch it), **CAUGHT-OTHER** when some other test failed but none of the named ones (the catch is real; the named test was wrong or absent), **SURVIVED** when the whole run was green (the suite cannot see the break). Sweeps run on detached COPIES of the reader's tree (`git worktree add --detach`), never on a watched tree, each part through `/data/dev/swarm/bin/slot claims <label> -- python3 -B mutate_origin.py <prefixes>` with `SLOT_MEM=2G` and `TMPDIR` inside the copy.

## Honesty notes (what the sweeps got wrong, found, and what they cannot say)

1. **Sweep 2's two «SURVIVED» (N02, N03) were faults of the INSTRUMENT, not of the suite.** `mutate_origin.py`'s `TESTS` list omitted `tests.tools.test_resit.TestEarlyLate`, where those two mutants of `classify_early_late` are pinned, so no test the sweep ran could see them. Both `mutate-origin-2.log` and the separate N-series run `mutate-origin-2N.log` read them SURVIVED (the same instrument); the list was then corrected (`TESTS` now carries `tests.tools.test_resit.TestEarlyLate`) and N02 and N03 re-run alone: `mutate-origin-2N-rerun.log` reads both CAUGHT. The tables read the later line of a mutant.
2. **Sweep 2's two «CAUGHT-OTHER» (O24, O25)** were caught by real tests whose names do not contain the substring the mutants had named (`partition`); the expected names were corrected to the tests' real names. The catch is the same in every sweep.
3. **The script that ran sweeps 1 and 2 was edited in place** (the `TESTS` line, the two expected names, then N14 and N15 for the separate counts); only the final version is committed here (`mutate_origin.py`, sha256 in `SHA256SUMS`). The earlier logs show each verdict under the version that ran them.
4. **A sweep is a list, not a proof.** The mutants are the breaks I could think of (and the verifier's findings turned into two more: N14, N15); an unthought break is not tested, and a mutant equivalent to the original would read SURVIVED (none did).
5. **A test listed as «the test that now kills» a sweep-1 survivor can predate the sweep.** The sweep prints the FIRST THREE failing test names, sorted, cut to 48 characters; a test introduced at 850b064 or 68ff83a that fails under a mutant now fails because the PRODUCTION code changed beside it (C08: `verify_source_copy` now reports any symlink, a82ea77), not because the test is new. Where a printed beginning is shared by two tests, both are listed.
