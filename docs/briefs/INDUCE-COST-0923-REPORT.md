2. **The margin under the bar is thin, and it shrinks as the creature learns.** Over the 290 measured canvases, filed rules rose 30 → 37 and the gemvs 2,032 → 2,788 a think. ## 3 · The change (`genome/think.py:induce`, 31 lines in, 6 out)
- **Index:** the ring is walked ONCE with the old expression `str(episodes.word[i])` (word → its slots, ascending: exactly the slots, in the order, the old per-word scan visited). `words_seen = sorted(slots_of)` is the same set and order. The answer map `answer_of` is built by the verbatim line and inverted ONCE (`answering`: word cell → alive sight cells, ascending). `C = sorted(answering.get(word_cell, []))` is a FRESH list per word: two words can light one word cell (dog/zog on the toy), and `row["cluster"]` must never alias.
- **Exit 1**, fewer than k episodes: `agree <= len(slots) < k`, so no rule is possible and `recall()` is not asked. **Exit 2**, an empty cluster: the old `and C` could never pass, so no gemv is run. **Exit 3**, the first counter-example: `disagree > 0` already refuses the rule, so the scan stops (`break`). An EMITTED rule still scans every slot, so its `agree` and `episodes` (slot order ≠ id order after the ring wraps) are unchanged.
- **Unchanged:** `ids`/`M`/`answer_of` (the 09-22 hoist's two lines, verbatim), `recall(...)["lit"]`, `_nearest_in` (not edited: `tools/verdict_g4.py` and `machinery.py`'s comment name it), the `_file(...)` call and its f-strings, `due=f"moment {org.t}"`. Every deciding nearest is `_nearest_in(ids, M, episodes.x_s[i])`: the same objects, the same gemv.

## 4 · Why the refused roads are different float paths (`scratch/toy/*.py`, seeded, re-runnable)
- `rowcount_probe.py`: 2,000 random alive matrices (D = 144, 20–200 rows). One appended row moved another row's `M @ x` value (bitwise) in **902**; one removed row in **1,780**. A nearest cached across thinks, while births and merges move the alive set, would carry values the current gemv does not compute.
- `lastbit_probe.py`: pairs of rows whose exact dot products with x are EQUAL (b = a with two components swapped where x_i = x_j): the gemv rounded them apart in **8,065 of 20,000** tries, and a single-row `a @ x` rounded differently from the same row inside the gemv. The toy pin plants one such road (`ape`, §1 (a)): its verdict exists only because of the gemv's own rounding.

## 5 · For the orchestrator — two findings that reach beyond INDUCE (lesson candidates; not written into the corpus from a builder lane)
- **A hoist can only remove REDUNDANT work; measure the decomposition before designing.** The brief (from a profile) read the gemv term as O(words × ring). The code already did one gemv per worded episode, and the redundancy lived in the string scan. The ≤ 10 % bar was reachable only through exits read off the EMISSION PREDICATE (`agree >= k and disagree == 0 and C`): work whose result cannot change what is emitted. One read-only measurement (`measure_induce.log`, before any code) said so in numbers.
- **On this box's BLAS a row's `M @ x` value depends on the OTHER rows.** One appended row moved another row's value in 902 of 2,000 random matrices; one removed row in 1,780 of 2,000. So any float cached across a changing matrix (the alive set moves every birth and merge) is a different float path, whatever the algebra says. The only exact caches are within one call, on one M.
