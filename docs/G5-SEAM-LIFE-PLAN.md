## 0 · The shape
- **A seam life = 8 h**, the WORLD line's `arrivals every 2 h` → windows 0,1,2,3 (the maker: even windows show THINGS_11; odd windows show THINGS_ARRIVAL2 + 3 of THINGS_11 drawn on (seed, window)). Three lives a day. The 24 h life stays for the verdict lives (the first G5 life with everything ON).
- **Which code:** one commit per life. The seam lives run from the INTEGRATION worktree `/data/dev/genome-wt-q` (branch `g5-integration`), pinned at the merge commit the life was started on; `/data/dev/genome` (master) is not moved while life 3b runs (`creature.service` imports from that tree; a closed tape replays only under its own commit — Builder E's fact, 2026-09-21).
- **Which root:** a seam life's root lives OUTSIDE every worktree: `/data/dev/genome-lives/g5-seam-<n>-<stamp>/` — so a worktree can be reset without touching a life's record, and the closed roots under /data/dev/genome stay the G4 lineage.
- **Which unit:** a second user unit `creature-g5.service` (WorkingDirectory = the integration worktree; `--root` the life's root; the same `OPENBLAS_NUM_THREADS=1`), enabled so a reboot resumes it; a second watch (`creature-watch` today watches `creature.service` only → a templated `creature-watch@<unit>.timer`, or a second timer naming the seam unit and root). Two creatures on 16 cores at ~1 thread each: fine; the builders' suites are the real load (they run under `nice -n 10`, ≤ 3 workers).

## 1 · What the reader (`tools/verdict_g4.py`) does on an 8 h tape — READ 2026-09-21 20:5x
- **Windows are read from the tape**, not from a clock: `meta.moment` is `w<window:04d>…` on every maker row; MODULATION and (v) walk the rows. `--hours 8` cuts the tape; ALIVE grades every FULL hour (canvases, thinks, snapshots, sleeps all > 0 in each) — cadence-agnostic. ✔ No window logic to change.
- **`--slice-hours` (default 6)** feeds only (ix), the random-genome slice → pass `--slice-hours 2` for a seam life.
- **THE PLANT WOULD NEVER SHOW (#228 (a)):** `world_maker.PLANT_AFTER_CANVASES = 15000` (hour ~21 at 0.2 canvases/s); an 8 h life has ≈ 5,760 canvases. `sense()` already takes `plant_after_canvases`, but `creature/body.py:main` never passes it → add a `--plant-after N` CLI knob (the unit's ExecStart carries it; the reader's (vi) needs zog shown 5 times, whenever). For a seam life: `--plant-after 5000` (hour ≈ 6.9, inside window 3, ≥ 1 h before the cut so the 5 showings over `PLANT_WINDOW_S` = 3600 s all land before 8 h). Refusing test: a 20-min temp-root life with `--plant-after 60` shows zog exactly 5 times on the tape; without the flag 0 (the old default).
- **THE EXAM would miss whole windows:** `EXAM every 2000 canvases` ≈ 2.78 h (life 3a: ONE exam file in 2.8 h; life 2: nine in 22 h); an exam costs 2.1–2.3 s (its own `seconds` field). (v) needs the LAST exam of an odd window vs the LAST of the preceding even one → for 2 h windows **`EXAM every 500 canvases`** (≈ 42 min; ~2.6 per window). K's SIT line extends EXAM; the number is set in G5.genome, not by K.
- **MODULATION's regime calibration** derives the null band from window-0 rows at `step = 100` (life 3b: n 150 fake boundaries over 6 h); a 2 h window 0 ≈ 1,440 canvases → ≈ 14 samples for a 95th percentile. Before the first seam life: expose `--regime-step` (25 → ≈ 57 samples) and print `n_w0_rows` and the sample count beside the band; the closed lives (2, 3a, 3b) re-read with the same step as the control (their verdicts must not move). The `len(w0) > 200` guard for the fixed null holds (1,440 > 200).
- **SLEEP under BIND (Builder J's seam clause, sent 20:5x):** `SLEEP every 2000 moments` is 42 min today (4 moments a canvas) and 2.8 h under BIND (1 moment a canvas) → ALIVE would FAIL by construction (an hour with 0 sleeps). G5.genome re-expresses every moment-denominated cadence J lists (SLEEP, SCALE, STAGE, BUDGET, FAST) to keep the wall-clock cadence, or records why a gene is per-moment by meaning.
